# Implement Frontend Library — Especificação

> **Status:** DONE
> **Data:** 2026-07-17
> **Módulo:** `frontend` (biblioteca + reader) + `backend` (conversion)

---

## Purpose

Implementar a biblioteca funcional do frontend com listagem real de conversões, visualização de capas, leitura multi-formato inline (EPUB/PDF/CBZ), ações sobre conversões (cancelar/remover/reconverter), wizard de reconversão, e correção de 5 bugs críticos no backend.

---

## Requirements

### Requirement: Listagem paginada de conversões

The system MUST provide a paginated list of conversions owned by the authenticated user, with optional filters.

#### Scenario: Listagem básica
- **WHEN** o frontend chama `conversionsApi.list()`
- **THEN** envia `GET /api/conversions` com Bearer token
- **THEN** retorna `{ items: ConversionSummary[], total, page, limit }`
- **THEN** cada `ConversionSummary` inclui `conversionId`, `sourceId`, `title`, `status`, `progress`, `totalJobs`, `completedJobs`, `failedJobs`, `createdAt`, `updatedAt`, `finishedAt?`, `cover?`

#### Scenario: Filtro por múltiplos status
- **WHEN** o frontend chama `conversionsApi.list({ status: ['queued', 'processing'] })`
- **THEN** envia `GET /api/conversions?status=queued,processing`
- **THEN** o backend splita a string e filtra por `status IN (...)`

#### Scenario: Filtro por sourceId
- **WHEN** o frontend chama `conversionsApi.list({ sourceId: 'src-abc' })`
- **THEN** envia `GET /api/conversions?sourceId=src-abc`
- **THEN** retorna apenas conversões daquela obra

### Requirement: Campo cover no ConversionSummary

The system MUST include the cover reference in the conversion summary response.

#### Scenario: Cover presente na resposta
- **WHEN** uma conversão foi criada com `cover: { kind: "original" }`
- **THEN** o campo `cover` está presente em `GET /api/conversions` e `GET /api/conversions/:id.config`
- **THEN** o schema Zod `conversionSummarySchema` inclui `cover: coverSchema.optional()`
- **THEN** o serializer Fastify não stripa o campo

#### Scenario: Cover ausente (legado)
- **WHEN** uma conversão foi criada sem campo `cover` (dados legados)
- **THEN** o campo `cover` é `undefined` ou ausente na resposta
- **THEN** o frontend trata como "sem capa" e mostra placeholder

### Requirement: Download de arquivo de saída

The system MUST serve the output file (EPUB/MOBI/CBZ/PDF) generated by KCC for a completed Job.

#### Scenario: Download de EPUB
- **WHEN** o frontend faz `GET /api/conversions/:convId/jobs/:jobId/download`
- **THEN** o backend valida ownership e existência do Job
- **THEN** streama o arquivo com `Content-Type: application/epub+zip`
- **THEN** inclui `Content-Disposition: attachment; filename="Vol 1.epub"`

#### Scenario: Job não pertence ao usuário
- **THEN** retorna 403 Forbidden

#### Scenario: Job não encontrado ou sem outputFile
- **THEN** retorna 404

### Requirement: Serve de capa cacheada

The system MUST serve cached cover images for scraped sources, publicly accessible.

#### Scenario: Capa "original"
- **WHEN** o frontend faz `GET /api/conversions/source/:sourceId/covers/original`
- **THEN** busca `source.covers.find(c => c.type === 'original')` com fallback para `source.covers[0]`
- **THEN** se cacheada em disco, serve direto
- **THEN** se não cacheada, baixa do provider, cacheia e serve
- **THEN** retorna com `Content-Type: image/jpeg` (ou png/webp) e `Cache-Control: public, max-age=86400`

#### Scenario: Capa de galeria por coverId
- **WHEN** o frontend faz `GET /api/conversions/source/:sourceId/covers/:coverId`
- **THEN** busca `source.covers.find(c => c.id === coverId)`
- **THEN** mesmo fluxo de cache e download

### Requirement: Hard-delete de conversão

The system MUST permanently delete a conversion and its jobs from the database.

#### Scenario: Delete com sucesso
- **WHEN** o frontend faz `DELETE /api/conversions/:conversionId`
- **THEN** valida ownership
- **THEN** remove a linha `conversions` (cascade deleta `conversion_jobs`)
- **THEN** retorna `{ conversionId, status: 'deleted' }`

### Requirement: Cancelamento de conversão

The system MUST cancel a running conversion without removing it from history.

#### Scenario: Cancel com sucesso
- **WHEN** o frontend faz `POST /api/conversions/:conversionId/cancel`
- **THEN** valida ownership e estado (não pode cancelar já terminal)
- **THEN** remove jobs pendentes da fila BullMQ
- **THEN** atualiza status para `cancelled`
- **THEN** retorna `{ conversionId, status: 'cancelled' }`

### Requirement: Biblioteca index com capas

The library index MUST display conversions grouped by source, with cover images, search, and status filters.

#### Scenario: Grid view com capas
- **WHEN** o usuário está em `/biblioteca` no modo grid
- **THEN** cada card exibe a capa da obra (`aspect-[2/3]`, imagem preenche sem padding)
- **THEN** o título da obra aparece sobreposto no rodapé da imagem
- **THEN** abaixo: contagem de conversões + tempo relativo da última atividade
- **THEN** cards têm fundo amarelo (`ComicPanel bg="yellow"`) com tilt alternado

#### Scenario: List view com capas
- **WHEN** o usuário alterna para modo lista
- **THEN** cada linha exibe capa (thumbnail 16x12) + título + status badge + tempo relativo
- **THEN** sem capa: placeholder com ícone `Library`

#### Scenario: Busca por título
- **WHEN** o usuário digita no SearchBar
- **THEN** filtra grupos cujo título contém o termo (case-insensitive)
- **THEN** destaca o termo no resultado (`highlightMatch`)

#### Scenario: Filtro de status (abas)
- **THEN** aba "Todas": mostra todos os grupos
- **THEN** aba "Em Andamento": filtra por status `queued` ou `processing`
- **THEN** aba "Concluídas": filtra por status `completed`

### Requirement: Detalhe da obra

The source detail page MUST list all conversions for a specific work with actions per conversion.

#### Scenario: Lista de conversões
- **WHEN** o usuário clica em uma obra no index
- **THEN** navega para `/biblioteca/$sourceId`
- **THEN** exibe todas as conversões daquela obra com capa, título, status, progresso, jobs, tempo

#### Scenario: Ações por conversão
- **THEN** ícone `ScrollText`: link para `/biblioteca/converter/$jobId` (log de conversão)
- **THEN** botão Cancelar (`XCircle`): visível apenas se status `queued` ou `processing`
- **THEN** botão Remover (`Trash2`): sempre visível, chama hard-delete

#### Scenario: Link para leitor ou progresso
- **WHEN** status é `completed`: link para `/biblioteca/reader/$conversionId`
- **WHEN** status não é `completed`: link para `/biblioteca/converter/$jobId`

#### Scenario: Reconverter
- **WHEN** usuário clica em "Reconverter"
- **THEN** navega para `/wizard?sourceId=...&conversionId=...` com dados da última conversão

### Requirement: Leitor multi-formato

The reader MUST support inline viewing of EPUB, PDF, and CBZ files, with a download-only fallback for MOBI.

#### Scenario: Seleção de volume
- **WHEN** o usuário acessa `/biblioteca/reader/$conversionId`
- **THEN** exibe lista de Jobs completed com `outputFile`
- **THEN** cada card mostra título e nome do arquivo

#### Scenario: Leitura de EPUB
- **WHEN** usuário seleciona um volume EPUB
- **THEN** baixa o arquivo como `ArrayBuffer`
- **THEN** renderiza via `<ReactReader url={arrayBuffer}>` com `location={null}` e `locationChanged`
- **THEN** o livro carrega sem erro "Error loading book"

#### Scenario: Leitura de PDF
- **WHEN** usuário seleciona um volume PDF
- **THEN** baixa o arquivo como blob URL
- **THEN** renderiza via `<iframe src={blobUrl}>` em container `h-screen`
- **THEN** o PDF ocupa toda a altura disponível (não colapsa em 150px)

#### Scenario: Leitura de CBZ
- **WHEN** usuário seleciona um volume CBZ
- **THEN** baixa o arquivo como blob
- **THEN** extrai imagens via `JSZip.loadAsync(blob)`
- **THEN** renderiza galeria com navegação prev/next e contador de páginas

#### Scenario: Download de MOBI
- **WHEN** usuário seleciona um volume MOBI
- **THEN** exibe tela: "Formato MOBI não pode ser visualizado no navegador"
- **THEN** oferece botão "Baixar MOBI" via `<a download>`

### Requirement: Wizard de reconversão

The wizard MUST accept query parameters to prefill data from an existing conversion.

#### Scenario: Prefill de reconversão
- **WHEN** o wizard recebe `?sourceId=src-xyz&conversionId=conv-abc`
- **THEN** carrega os metadados da source via `scrapingApi.getSource(sourceId)`
- **THEN** carrega o config da conversão via `conversionsApi.get(conversionId)`
- **THEN** preenche: sourceId, inspectData, selectedChapters, device, format, preset, options
- **THEN** salta para step 2 (capítulos)

### Requirement: Bug fixes

The system MUST correct 5 critical bugs.

#### Scenario: Scraping não perde capítulos
- **WHEN** o parser processa links de capítulo
- **THEN** usa match exato de token CSS (`classTokens.includes('c-btn')`) em vez de substring (`elClass.includes('c-btn')`)
- **THEN** não filtra indevidamente links como `c-btn-new` (que contém 'c-btn' como substring)

#### Scenario: Swagger não quebra
- **WHEN** o Swagger UI carrega
- **THEN** os endpoints de download e cover NÃO incluem `response: { 200: { type: 'string', format: 'binary' } }`
- **THEN** `jsonSchemaTransform` não encontra raw JSON objects e não quebra com 500

#### Scenario: Reader não fica em loading infinito
- **WHEN** a lista de jobs carrega com sucesso
- **THEN** `setLoading(false)` é chamado no caminho de sucesso

#### Scenario: Ícone de log visível
- **THEN** cada card de conversão em `$sourceId` exibe botão `ScrollText` linkando para `/biblioteca/converter/$jobId`
